## A. 门禁 fail-open(安全,最高优先级)—— `scripts/claude-hooks/check_commit.py` + `pre-commit-review.sh`

| # | 问题(实测) | 修复方案 |
|---|---|---|
| A1 | **粘连操作符绕过**:`git commit&&git push`、`git commit;ls`、`git commit\|less` 均 rc=1 放行(norm() 只 rstrip 尾部,`commit&&git` ≠ `commit`) | norm() 改为**把 shell 操作符(`;&\|<>&` 等)作为 token 分隔符拆分**:先 `re.split(r'[;&\|<>&]+', cmd)` 再逐段扫 git+commit;或用 shlex 分词后处理 |
| A2 | **SKIP 字符串误命中**:`git commit -m "CLAUDE_REVIEW_SKIP=1"`、`echo CLAUDE_REVIEW_SKIP=1 && git commit` 绕过(无锚点子串匹配 toks[:4]) | SKIP 检测**锚定命令首**:仅当 `toks[0]` 是 `CLAUDE_REVIEW_SKIP=1` / `$env:CLAUDE_REVIEW_SKIP=1`(可带空格)的 env 赋值形式才放行;提交信息里的字符串不再命中 |
| A3 | **全路径 git 绕过**:`C:\Program Files\Git\cmd\git.exe commit`、`git-commit` 不识别 | is_git() 改按 **basename 判断**:token 末段(`split(/\\\)[-1]`)∈ {git, git.exe, git.bat, git.cmd, git-commit} 即命中 |
| A4 | **merge/pull/cherry-pick/revert/rebase --continue 不拦截**(产生提交但不审查) | 检测增加**产生提交的子命令集合**:{commit, merge, pull, cherry-pick, revert, rebase, am, commit-tree}(merge/pull 需再判是否真产生提交,保守拦截可 SKIP) |
| A5 | **python 异常 = 全会话 DoS**:python 缺失/JSON 解析异常 → exit 2 拦所有 Bash/PowerShell 命令 | fail-closed 收窄:仅当**检测器确认是 git commit 且检查中异常**才 exit 2;JSON 解析失败/python 不可用 → exit 0 放行(检查是附加的,只拦不放) |
| A6 | **32KB payload 阻塞**:payload 作为 argv 传 python,Windows 限制 ~32KB → 大命令全被拦 | 改 **stdin 传 payload**(`python check_commit.py <<< "$payload"` 或 `printf %s "$payload" \| python ... -`),无长度限制 |
| A7 | **flag 值恰为 "commit" 误拦**:`git -C commit log`(目录名 commit)被当提交 | 先消费 flag 值再判断子命令:expect_val 分支优先,`w=="commit"` 且 expect_val=True 时作值处理 |
| A8 | **跨仓库 `-C` 检查错仓库**(latent,当前单仓库) | 检测到 `-C`/`--git-dir` 且目标 ≠ 本项目时跳过门禁(或解析目标仓库);低优先 |
